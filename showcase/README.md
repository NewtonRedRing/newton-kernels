# NewtonKernels capability showcase

A framework-free, responsive, accessible static benchmark dashboard. HTML/CSS/JS are original, and competitors' source code is **not** bundled.

## Open locally

```sh
python3 tools/build_showcase.py --check
python3 -m http.server 8000 --directory showcase
# Open http://localhost:8000
```

For a clean rebuild of the site data:

```sh
python3 tools/build_showcase.py
```

`showcase/data/results.json` is generated byte-for-byte from a committed, equal-output-verified source file. A predeployment check refuses missing or inconsistent results.

## GitHub Pages publishing

The workflow `.github/workflows/showcase-pages.yml` validates the committed evidence and packages the `showcase/` directory. Every run uploads a **newton-kernels-site-preview** artifact first, available under the run's **Artifacts** section even before the public site is enabled.

**One-time repository-owner action:** open [Settings → Pages](https://github.com/NewtonRedRing/newton-kernels/settings/pages), then under **Build and deployment → Source** choose **GitHub Actions**. After GitHub initializes Pages, rerun the [Publish capability showcase](https://github.com/NewtonRedRing/newton-kernels/actions/workflows/showcase-pages.yml) workflow (or push a change to `showcase/`).

The default workflow `GITHUB_TOKEN` cannot initialize a Pages site: GitHub's `actions/configure-pages` explicitly requires an additional credential with administration and Pages write access for `enablement: true`. We do **not** store or request such a credential; the one-time owner setting is safer. After initialization, the standard `pages: write` and `id-token: write` workflow permissions are sufficient for publishing.

Intended public address: `https://newtonredring.github.io/newton-kernels/`. Treat the actual GitHub Pages deployment result as authoritative; **do not announce the site live until deployment succeeds and the address loads**.

## Claims policy

1. No simulated measurements or competitor code copying.
2. Show both competitors' raw values; measurements with ratio below 1× remain visible.
3. Memory is labeled **whole-process RSS**. Never infer a library-memory advantage from it.
4. Show unmeasured areas as “Not measured,” not “coming wins”.
5. All tested and reported input sizes remain visible in the data and available with an 'all' filter.
6. Do not imply graph construction or CSV file-backed parallel parsing is included in current results.

## Expanded eight-module evidence

Use the **Benchmark host / campaign** selector to switch between the full 22-case CI run and the 16-case local VM study. These campaigns are not combined into one timing ranking. The same-input results include standard-library reference wins, and the CSV and Boost comparisons have a different host from the five-module study.

The supported raw sources are [`data/results.json`](data/results.json) and [`data/extended-results.json`](data/extended-results.json). Refresh them from their separately committed original evidence with `python3 tools/build_showcase.py` and validate with `python3 tools/build_showcase.py --check`.
