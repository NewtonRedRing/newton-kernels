Project / NewtonKernels 0.1

Documentation lifecycle and repository hygiene

Keep public docs discoverable while retaining reproducible evidence and historical engineering decisions.

Sources of truth

  • API contracts: include/newton/ and behavioral tests.
  • Build and package: CMake configuration and installed consumer tests.
  • Measurements: committed benchmark results and unmodified raw samples.
  • Public Pages: showcase/; hosted through the GitHub Pages workflow.
  • Research history: dated audit, experiment and roadmap Markdown documents.

Cleanup decisions

Generated build directories, profiler outputs, Python caches, editor files and local temporary logs belong outside Git tracking. The repository's .gitignore prevents common accidental additions. Files required to reconstruct benchmark claims are not junk, even if they are generated.

The site JSON under showcase/data/ is an intentionally committed, reproducible copy of pinned evidence. The site workflow checks byte-for-byte agreement with its source; deleting it would break offline GitHub Pages publication.

Archived engineering material

One-off experiment notes and implementation plans remain in the Markdown documentation directory but are separated from recommended entry-point guides in its index. Deleting those documents would lose rationale and evidence provenance.

Maintenance review sequence

  1. Review the recursive Git tree for generated binary, temporary and unused material.
  2. Check Markdown and website references, navigation and accessible structure.
  3. Validate data integrity with python3 tools/build_showcase.py --check.
  4. Run python3 tools/check_docs.py for local link and fragment integrity.
  5. Run required CI and performance checks before merging.
