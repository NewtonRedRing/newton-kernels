Reference / NewtonKernels 0.1

Architecture and contracts

Small, independently linked native components; explicit data ownership; optimizations validated against portable behavior.

Library boundaries

Modules under include/newton/ expose public C++20 headers. Compiled libraries under src/ can be linked independently where practical. Template and header-only extensions remain opt-in. There is no required scheduler service, daemon, JIT or managed runtime.

InputsMapped files, strings, spans and borrowed columns supplied by the caller.
KernelsParsing, SIMD, indexing, analytics and graph operations with narrow contracts.
ExecutionSynchronous functions by default; explicit Executor only when requested.
EvidenceCorrectness tests, sanitizers, fuzzing and paired benchmark guard checks.

Portability and dispatch

The CPU features module detects usable instruction support. Selected x86 routines can dispatch AVX2 or AVX-512 implementations, with portable scalar paths for other supported platforms. This does not imply every algorithm is vectorized or that an ISA is always faster.

Error and exception boundaries

APIs use argument checks, exceptions and documented overflow behavior. C ABI entry points instead expose status codes. Allocation-failure and exception-safety tests are important release gates; passing unit tests alone does not prove all possible failure paths.

Explicit non-goals

This development preview is not a distributed cluster runtime, SQL engine, GPU framework, persistent index server or full Unicode search stack. Proposed future architecture is recorded separately and should not be mistaken for shipped functionality.
